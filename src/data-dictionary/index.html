Data dictionary

This guide explains key fields in the public research export. Fields may be absent or vary between records; consult the machine-readable schema for exact structures.

FieldMeaning
idStable project identifier used for internal references and URLs.
nameResearch listing name; not necessarily the legal name of a facility.
where, country, regionHuman-readable geography and regional grouping.
infrastructureTypeReported infrastructure class, such as dock, station, hub or network.
reportedOperatorOperator named in source reporting, not independently verified ownership.
reportedEquipmentEquipment specified in the public source, if known.
approximateMapPointMap visualization coordinates; not operational landing coordinates.
locationPrecisionExplanation of how exact or approximate the geographic representation is.
reportDateLabelDate context of the cited report, not necessarily the last operational date.
sourceSupporting source name and URL.
verificationStatusEditorial evidence/verification descriptor. Read alongside the source and methodology.

Filtered exports

Use the project directory to export the current search, country, category and sort order as JSON or CSV. Filtered JSON retains complete original record objects in records, with count, filters, exportedAt and research limitations. The export timestamp is the download preparation time, not the date the research was verified.

Correction report schema 1.1 includes requestedProjectId, contextResolution and requestedReferenceTruncated. An unresolved reference stays explicitly unresolved, with no claimed project passport; retrying a lookup invalidates any older prepared preview. Correction reports are a separate format: they include the project ID, original reported details and your proposed changes. The report preparation form works locally and does not deliver reports to an inbox.

Research audit exports

The data-quality page exports all records or flagged records as CSV or JSON. Audit JSON stores the original object in records[].record and review messages in records[].flags. An explicit unverified-date flag reflects the existing date label, not a new finding about the source. No flags means these metadata checks found nothing to flag; it does not verify accuracy or operations.

Single-project exports

Each project passport offers a project JSON download. It wraps the unchanged research object in records with count: 1, an export timestamp and research limitations. It does not provide verified contact details, operating status or flight permission.

Directory browse filters

The directory supports exact country, infrastructure type and region filters, plus text search and report year. Report year is extracted from the existing report-date label, including labels explicitly marked unverified. “Unspecified” selects labels without a recorded year; it does not mean the source has no publication date.

Copied directory links and filtered JSON include the active region and year. The research records themselves are unchanged.

Filtered research review

The data-quality review queue can be filtered by text, country and review flag. These filters only select flagged records; they do not change any research record or establish operational accuracy.

The “Current review view” audit scope exports those selected entries with their flags. JSON includes reviewFilters and scope: review. All records and Flagged only retain full-dataset scopes. A copied review link shares filters; export scope is selected separately.

A missing map point is distinct from an invalid point. Duplicate IDs remain in audit exports but do not receive project links until their identity is resolved.

Project comparison

Select Compare on up to three directory cards to compare reported country, region, location, category, operator, equipment, location precision, report-date label and evidence status. Selections remain available when directory filters hide a selected card.

Comparison JSON contains the original selected research records, selection order and limitations. Comparison CSV includes a subset of those fields and neutralizes spreadsheet formula prefixes. A comparison link shares the selection independently of directory filters. These comparisons do not establish affiliation, compatibility, active operations, site access or flight permission.
